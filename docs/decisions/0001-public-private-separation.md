# 0001: Separate public and private repositories

Status: accepted

## Decision

Maintain this project as a fresh, public-only repository rather than publishing or rewriting the production repository.

## Rationale

A separate history creates a verifiable boundary and avoids exposing deleted material through old commits. The public project receives only purpose-written code and individually approved assets. It is not a deployable substitute for production.

## Consequences

Features are intentionally incomplete, production changes do not automatically flow here, and every addition requires independent publication review. This duplication is accepted because disclosure prevention is the higher priority.
